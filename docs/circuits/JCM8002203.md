# JCM800-Style Amplifier (Marshall JCM800 2203, 100 W master-volume lead)

Display name **"JCM800-Style Amplifier"** (category Modeled Amps), registry key `JCM800StyleAmplifier`. Runs on
[`NodalCircuit`](./NodalCircuitSolver.md). Code: `Source/Effects/JCM800StyleAmplifierProcessor.{h,cpp}`, tests
`Tests/JCM800StyleAmplifierProcessorTests.cpp`. (The amp is a Marshall product; the "-Style" convention applies.)

**Which amp**: the 100 W 2203, the single-input "master-volume lead" head that gave the whole JCM800 line its name and
became a defining hard-rock/metal preamp sound of the 1980s. The power section (phase inverter, four EL34s as two
pairs, output transformer, global feedback, Presence, supply) is **structurally identical** to
[`SuperLeadStyleAmplifierProcessor`](SuperLead1959.md)'s own -- both are 100 W 4xEL34 Marshalls -- and reuses that
already-verified code and EL34 tube fit unchanged. What's genuinely different, and newly built here, is the
**preamp**: unlike every other amp on this project's roadmap so far (two input channels, each with one gain stage,
mixed together), the 2203 has a SINGLE input (High/Low sensitivity jacks sharing one gain stage) driving FOUR CASCADED
gain stages in series (V1a -> Gain pot -> V1b -> V2a -> V2b, the last a cathode follower into the tone stack) -- the
real source of this amp's much higher gain and "master volume lead" character.

## Source
`schematicheaven.net/marshallamps/jcm800_lead_mstvol_100w_2203.pdf` ("2203 STD"), fetched via `curl` and read from the
rasterized drawing at 300 dpi (overview downscaled, specific regions re-read at full resolution for component values).
The single most iconic JCM800 model, and the one this whole product line is best known for.

## What is modelled
```
guitar -> High or Low sensitivity jack (a plain input attenuation, High=1.0/Low=0.25 -- see "Reading choices" below)
       -> 68k grid stopper -> V1a (2k7 || 68 uF cathode: full bass, no local NFB, 100k plate)
       -> 0.022 uF -> Gain pot (VR1, 1M log; R5 470k / C4 470 pF / C5 1 nF bridging its own top-to-wiper segment)
       -> V1b (10k cathode, UNBYPASSED: real local negative feedback, 100k plate)
       -> 0.022 uF -> (470k to ground, 470 pF bright cap) -> V2a (820 R cathode, UNBYPASSED, 100k plate)
       -> V2b: an IDEAL cathode follower (DC-coupled directly off V2a's plate, no capacitor between them)
   [power block, reused unchanged from the Super Lead -- see that doc for the full breakdown]
       -> 531 R follower output impedance -> Marshall TMB stack: 470 pF, 33k, 220k treble, 1M bass (a rheostat),
          22k middle (tapped), 2 x 22 nF -> V3 long-tailed pair -> two EL34 pairs -> output transformer -> speaker
       <- 47k global feedback, 5k Presence, same topology as the Super Lead
   [bias supply / supply model] identical to the Super Lead's own
```
Controls (0..1), **page 1**: Input (High / Low sensitivity jack), Gain (VR1, the preamp's own single gain control),
Treble, Middle, Bass, Presence, Output (a plug-in level control). **Page 2**: Power Drive (the real amp's own Master
Volume, VR2), Bias, Tube Feel, Speaker (4/8/16 ohm). Unlike the Bassman/Super Lead/JTM45 family there is no second
channel and no Loudness I/II pair -- one Gain knob ahead of the tone stack, matching the real 2203's own front panel.

## Reading choices worth knowing
* **High/Low sensitivity modelled as a plain input scalar, not a separate resistor network.** Both jacks feed the
  exact same V1a grid on the real amp (through different loading), so a scalar (High = 1.0, Low = 0.25) captures the
  practical effect (Low is quieter/less prone to front-end overload) without a second unverified resistor guess.
* **The Gain pot's own bright-compensation network (R5/C4/C5) was not fully legible at scan resolution.** Modelled as
  a fixed RC bridging the pot's own top-to-wiper segment (a standard trick for a log-taper gain control), which is
  plausible but not pixel-confirmed -- flag this first if the Gain knob's own taper/brightness feels off against a
  real 2203.
* **V1a/V1b share one preamp rail tap, V2a/V2b share the other**, matching the schematic's own two distinct preamp
  rail nodes (the same R14/R15-decoupled supply ladder the Super Lead's own two channels sit on, just with all four
  gain stages now in series on it instead of two channels in parallel).
* **Tone stack pot values read directly off this amp's own schematic**: Treble 220k linear (the Super Lead's own is
  250k), Bass 1M log, Middle 22k linear (the Super Lead's own is 25k) -- small, confirmed, real differences from the
  Super Lead's own tone stack, not copied blind.

## A power-stage instability, its fix, and why the reduced-order fit deliberately did NOT come from this amp's own reference model

Unlike the Super Lead (whose power section this circuit reuses byte-for-byte), the full-topology reference model
**self-oscillates from silence**: with zero input, the model grows from a clean idle point into a full-scale, chaotic
low-frequency oscillation of the phase inverter/output stage within under a second, and stays there indefinitely.
This is the same general failure class as [[circuit-tube-model-loop-instability]] (see also
`docs/circuits/DeluxeReverbAB763.md` and `JTM45Marshall.md`'s own writeups), but with a twist: the power section
itself is unmodified, proven-stable code. The only structural difference from the Super Lead is the preamp driving
it, so the working theory is that four cascaded gain stages (vs. two single stages mixed together) push a different,
apparently less stable, DC operating point onto the shared global-feedback loop.

**What was ruled out, via the same isolation tests used for the Deluxe Reverb/JTM45 cases:**
- **The global negative feedback loop.** Opening it entirely (`debugSetFeedbackResistance(1e9)`) did not stop the
  oscillation (a near-identical chaotic trace persisted) -- rules out the loop itself as the sole cause.
- **The supply's sag loop.** Freezing the supply's dynamic current-draw feedback at its idle value
  (`debugFreezeSupplyCurrent`) did NOT stop the oscillation either -- it instead became a clean, perfectly periodic
  limit cycle (~76-79 V amplitude, alternating sign every ~0.5 s), which per the standard diagnostic means the sag
  loop is not the cause (a real numerical/supply-coupling bug would typically vanish when frozen, not turn tidy).

**What does move the needle: softening BOTH the phase inverter's 12AX7 and the output EL34 pair's `kg1` together,
each by a modest 70x.** Splitting the correction across both tubes reaches genuine 10 s silence-stability with much
less damage to either one's own transfer curve than pushing the whole correction onto a single tube -- softening
EITHER tube ALONE needed an extreme multiple (~3800x on the PI triode alone, or ~3000x on the pentode alone) to fully
quench it, and at that extreme it also crushed the reference model's own ordinary-signal gain to near-silence (see
below). The local-only tube variants (`triode12AX7Pi()`, `pentodeEL34PairPower()`) live in this file's own anonymous
namespace and do not touch the Super Lead's own (separately defined, unmodified) tube fit.

**Real, disclosed cost: the full-topology reference model's own ABSOLUTE gain and saturation shape are now
unreliable for calibration.** A `J8_POWERCAL` sweep against the now-stable reference shows its speaker output has
collapsed to roughly 1/100th of a healthy amp's expected range (fractions of a volt where the Super Lead's own sweep
reaches tens of volts), and the sweep's own drive-vs-output curve is measurably non-monotonic through part of its
range (a real irregularity, not sweep noise -- each level point's own ~1.4 s settle time, itself a consequence of the
supply's slow B+ filtering, likely leaves some points still mid-transient at the 1.5 s measurement window used).
Fitting `bmGain0`/`bmYmax` to this data would bake a qualitatively wrong (not just quieter) compression curve into
the shipped default, not merely a quieter one the way the JTM45's own disclosed trim compensates for. **Decision:
`bmGain0`/`bmYmax`/`bmKneeN`/`bmShelfHz`/`bmShelfHfGain` are deliberately kept as the Super Lead's own already-fitted
numbers** (same power-section topology, same tube fit, and specifically verified healthy for this amp's own use --
see Verification below) rather than an independently but unreliably fitted fresh curve. This is a real, open gap:
revisit once the reference model's silence-oscillation has an actual root cause, not just a stability band-aid.

**What was NOT the cause, ruled out by direct instrumentation rather than assumption:** the preamp's own
`followerOut` node (feeding the power section) was found swinging wildly (~100-340 V) under a repeatedly-retriggered
decaying pluck test even while the power section's own tone-stack-output response stayed comparatively modest
(-12..+8 V) -- a real, not-fully-explained transient effect (grid-conduction/"blocking distortion" under heavy
cascaded drive is the leading suspect, though not confirmed) worth a closer look before this preamp pattern gets
reused for a future high-gain amp on the roadmap. Critically, this effect is confined to the FULL-TOPOLOGY reference
model exercising that specific note sequence -- the SHIPPED (reducedOrder) path never touches the PI/pentode nodes at
all, and was directly confirmed to stay healthy (peak 1.49, RMS 0.99, zero failures) for the exact same note
sequence (see `Tests/JCM800StyleAmplifierProcessorTests.cpp`'s "reducedOrder (shipped default): a plucked-note
sequence..." test).

**Working hypothesis, not confirmed**: like the JTM45's own unresolved case, the true root cause is likely something
structural not isolated within the time available -- the Gain pot's own uncertain R5/C4/C5 bright-network reading
(see "Reading choices" above) is the leading suspect for a future pass, since it is the one genuinely unverified
component value in the whole preamp chain and sits directly in the signal path feeding the rest of the cascade.

## Verification (`Tests/JCM800StyleAmplifierProcessorTests.cpp`)
* DC operating point sane (plate rail 480 V, PI rail ~383-387 V, V1/V2 preamp rails ~327-338 V, all in a decreasing
  chain matching the Super Lead's own convention; this amp's own drawing prints no rail voltages).
* **Silence settles over a full 10 s soak** (not 2 -- the JTM45/Deluxe Reverb lesson applies here too) with the
  kg1 fix in place: peak ~0.000001, zero failures.
* A plucked note through each Input (High/Low) setting stays finite with a low failure rate; the FULL REFERENCE
  model's own peak stays low here for the reasons discussed above -- the test intentionally only checks finite/failure
  rate, not loudness, for this specific case, with a comment pointing at the reducedOrder pluck test for what ships.
* `reducedOrder` tracks the (now-stable, if compromised) reference within 0.00-0.41 dB across a 5e-3 to 0.6 V sweep.
* `reducedOrder`'s own plucked-note sequence (same note stream the full reference model struggles with) stays
  healthy: peak 1.49, RMS 0.99, zero failures/recoveries.
* Speaker 4/8/16 ohm bit-identical (46.16 V rms each), same `speakerGain` convention as every other amp.
* `PedalUnityLevelTests` passes at 0.00 dB with a measured registry trim of **-17.47 dB**.

## Reduced-order (behavioural) power stage
Built in from the start. **Deliberately still the Super Lead's own fitted constants**, not an independent
`J8_POWERCAL` fit -- see "A power-stage instability" above for the full reasoning. Same mechanism otherwise; see the
Super Lead's own doc for the general methodology.
* **Known, documented gaps**: everything the other amps on this pattern already document (Presence/Bias/Tube Feel
  have reduced or no effect in reducedOrder), PLUS the un-independently-calibrated power-stage curve described above,
  the largest open item on this amp specifically.

## Cost
Shipped default (reducedOrder): ~8.6-9.0% average, up to ~18-44% worst block under a hot-pedal stress (higher worst-
block variance than the Super Lead's own numbers, likely a consequence of the much higher preamp gain reaching the
saturating curve harder under randomized hot-note stress). Orders {0, 0, 1}, same tier convention as the other amps.
Unity trim -17.47 dB.
