# CPU benchmark — A7S reference table (x86, 2026-10-11)

`RenderFx --bench` numbers for the Phase 6 Radxa Cubie A7S port (Allwinner A733).
Until now every CPU% we quoted came from `run_renders.py` on this x86 dev box at
its own settings; this table is the deliberate reference: **48 kHz, mono,
256-sample blocks (5.333 ms realtime budget)**, best-of-3 reps, DI
`Tests/fixtures/di/guitar-di.wav` (44.1 k stereo, downmixed + Catmull-Rom
resampled to 48 k mono inside the bench).

Two columns per effect:

- **high** — `OversamplingQuality::high`, the desktop reference tier.
- **reduced** — `OversamplingQuality::eco`, the tier the app ships at and the one
  sized for the A7S: minimal oversampling, and every amp already on its shipped
  `reducedOrder` power stage (those flags are unconditional in
  `registerBuiltInEffects`). This column is the device code path, measured on
  x86 for ranking only.

CPU% = processing_time / audio_time. `peak` is the slowest single block in the
fastest rep — a peak >5.333 ms means at least one realtime callback would have
been late even though the average fits.

## Reproduce on the A7S (one command)

The same `OpenGuitarMultiFx_RenderFx` target cross-builds in CI already
(`scripts/cross-build.sh aarch64` — Cortex-A76 tuning,
`OGMFX_TARGET_CPU=cortex-a76`). Copy the binary + fixtures and run the bench:

```sh
# on the dev box / CI artifact:
scripts/cross-build.sh aarch64
scp build-aarch64/Tests/OpenGuitarMultiFx_RenderFx_artefacts/Release/OpenGuitarMultiFx_RenderFx \
    Tests/fixtures/di/guitar-di.wav Tests/fixtures/lstm.nam \
    tools/fx-audit/ir/cab-4x12.wav radxa@<a7s>:~/

# on the device — produces the same table (all 123 effects, both tiers):
./OpenGuitarMultiFx_RenderFx --bench guitar-di.wav cpu-bench-a7s.csv \
    --nam=lstm.nam --ir=cab-4x12.wav
```

Parallel + per-key variant (what produced this file — needs python3, which the
A7S image already ships):

```sh
RENDERFX_BIN=./OpenGuitarMultiFx_RenderFx DI_WAV=guitar-di.wav \
NAM_FIXTURE=lstm.nam CAB_IR=cab-4x12.wav \
BENCH_CSV=cpu-bench-a7s.csv BENCH_MD=cpu-bench-a7s.md \
  python3 tools/fx-audit/run_cpu_bench.py
```

On heterogeneous cores pin to the A76 pair for a like-for-like column —
`BENCH_CORESET=0,1` (check `cpuinfo_max_freq` first to identify the big cores).

CSV columns: `effect,quality,sr,block,channels,reps,audio_ms,proc_ms,cpu_pct,
rtf,peak_block_ms,budget_ms,peak_block_pct,blocks_over_budget,status`.
Raw x86 run: `tools/fx-audit/cpu-bench.csv` (regenerate with
`python3 tools/fx-audit/run_cpu_bench.py`).

## >10% reduced-quality flags — and what is (not) trivially fixable

30 of 123 effects exceed the 10%-of-a-core bar at the reduced tier. They split
into three groups:

**a) Full netlist, no reducedOrder implemented (structural work, not a flag):**
- `SVTStyleAmplifier` 26.1% — registry comment says it outright: "No reducedOrder
  yet: the full reference netlist always runs."
- `KometConcordeStyleAmplifier` 19.6%, `TrainwreckExpressStyleAmplifier` 18.3% —
  same family, both full netlists.
The fix is the same behavioural power-stage pattern the other amps already got
(`*StyleAmplifierProcessor::reducedOrder`), i.e. real DSP work, not a flag flip.

**b) reducedOrder already on, still heavy at 1x (needs a cheaper preamp/stage,
not a flag):** EVH5150 19.6%, Rockerverb 18.6%, SLO100 11.8%,
BognerUberschall 11.5%, FryetteDeliveranceD120 10.6%, DualRectifier 10.1%.
These already run the A7S code path — the cost is the model itself.

**c) Pedals still at 2x oversampling at eco (`Orders{1,...}`) — the actual
one-line candidates.** Dropping the eco entry to 0 roughly halves the number.
Caveat: those orders were chosen from measured aliasing
(`docs/circuits/Oversampling.md`), so this is a sound-quality tradeoff to make
per pedal on the device, not a free fix:
- MetalZone 48.4% — even ~1x ≈ 24%, worst overall; the flag alone won't save it,
  it needs a reduced-order model like BD-2's.
- ToneBender 29.5%, HM-2 27.0%, Big Muff family 24–26% (BigMuff/Bass/Sovtek/
  Russian), TubeDriver 23.7%, ODR-1 22.8%, DT-1 21.5%, Darkglass B7K 18.7%,
  Si ToneBender 17.9%, SansAmp BDDI 14.9%, OCD 14.0%, CrunchBox 12.7%,
  Overdriver 12.6%, DS-1 12.4%, RAT/RAT2 ~11.5%, BD-2 10.5% (already on the
  reduced-order BD-2), TurboRat 10.3%.
- HM-2 extra note: it *has* a reducedOrder (27% → ~5.4%) but that path was
  deliberately reverted after a user-heard volume pop at hard edges — flagging
  it back on is one line but re-opens a rejected sound regression.
- BD-2 extra note: 10.5% is already the reduced-order path at 2x — its remaining
  headroom is the oversampling drop, not another model change.

**Peak-block overruns at reduced (34 effects):** most are 1–3 late blocks in the
best rep — a cold-start/transient (Newton solvers warming up), not sustained
load. The systemic ones (late blocks in double digits) track the group-c
offenders: ToneBender 58, HM-2 23, MetalZone 22, BassBigMuff 15, Sovtek 13/15,
SVT 9, KometConcorde 10, EVH5150 6, plus RiveraKnucklehead's single 13.5 ms
outlier. Worth a `--repeat` rerun on the A7S before acting on them.
