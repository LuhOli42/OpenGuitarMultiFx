Re-ran `RenderFx --bench` on `main` (4d26f8a) after the voicing/CPU merge
train (#59/#63/#65/#72/#77/#78/#79/#82/#83/#85/#86/#80). Same method as the
Oct-11 table: **48 kHz, mono, 256-sample blocks (5.333 ms realtime
budget)**, best-of-3 reps, pinned to a 2-core set via `BENCH_CORESET=0,1`,
DI `Tests/fixtures/di/guitar-di.wav`.

> Methodology fix vs round 1: the first bench pass of this refresh ran
> while `analyze.py` was still processing the render sweep and inflated
> every row (+10-25 pp on the heavy effects — e.g. MetalZone read 71.6%
> instead of 49.5%). This table is the quiet-machine re-run. Benchmark on
> an idle box only.

## Reproduce on the A7S (one command)

The same `OpenGuitarMultiFx_RenderFx` target cross-builds in CI already
(`scripts/cross-build.sh aarch64` — Cortex-A76 tuning,
`OGMFX_TARGET_CPU=cortex-a76`). Copy the binary + fixtures and run the bench:

```sh
# on the dev box / CI artifact:
scripts/cross-build.sh aarch64
scp build-aarch64/Tests/OpenGuitarMultiFx_RenderFx_artefacts/Release/OpenGuitarMultiFx_RenderFx \
    Tests/fixtures/di/guitar-di.wav Tests/fixtures/lstm.nam \
    tools/fx-audit/ir/cab-4x12.wav radxa@<a7s>:~/

# on the device — produces the same table (all 123 effects, both tiers):
./OpenGuitarMultiFx_RenderFx --bench guitar-di.wav cpu-bench-a7s.csv \
    --nam=lstm.nam --ir=cab-4x12.wav
```

Parallel + per-key variant (what produced this file — needs python3, which the
A7S image already ships):

```sh
RENDERFX_BIN=./OpenGuitarMultiFx_RenderFx DI_WAV=guitar-di.wav \
NAM_FIXTURE=lstm.nam CAB_IR=cab-4x12.wav \
BENCH_CSV=cpu-bench-a7s.csv BENCH_MD=cpu-bench-a7s.md \
  python3 tools/fx-audit/run_cpu_bench.py
```

On heterogeneous cores pin to the A76 pair for a like-for-like column —
`BENCH_CORESET=0,1` (check `cpuinfo_max_freq` first to identify the big cores).
When a coreset is given the runner caps its workers at that many cores so
benchmarks don't race each other for a shared core.

`--ir` feeds all three `IRLoaderProcessor` keys (Cab, DynamicCab, Reverb);
without one, `Reverb` would measure passthrough, not convolution. The Reverb
row uses the short cab-4x12 IR as the convolution workload — cost scales
~linearly with IR length, so a seconds-long reverb IR will measure higher
than the surrogate number below.

CSV columns: `effect,quality,sr,block,channels,reps,audio_ms,proc_ms,cpu_pct,
rtf,peak_block_ms,budget_ms,peak_block_pct,blocks_over_budget,status`.
Raw x86 run: `tools/fx-audit/cpu-bench.csv` (regenerate with
`python3 tools/fx-audit/run_cpu_bench.py`).
